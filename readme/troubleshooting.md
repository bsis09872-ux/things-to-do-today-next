## 기억에 남는 세 가지

### 1. 로그아웃했는데 회원가입으로 못 감 (라우터 캐시)

- **증상**: 로그아웃 → `회원가입` → `/sign_in?redirectUrl=%2F`로 다시 이동.
- **원인**: Next는 화면에 보이는 링크의 페이지를 미리 받아 둡니다(prefetch). 로그인 상태에서 받아 둔 `/sign_up`은 "이미 로그인했으니 홈으로"라는 응답이었고, 로그아웃 뒤에도 이 저장본을 그대로 썼습니다.
- **해결**: 로그아웃이 성공하면 페이지를 완전히 새로 열어(`window.location.replace('/sign_in')`) 저장본을 비웁니다.
- **배운 점**: "이동" 하나에도 서버 응답 · 브라우저 캐시 · 로그인 상태가 얽혀 있다는 것. 리다이렉트는 로그인 전후를 모두 따져야 합니다.

### 2. 오픈 리다이렉트와 허용 목록

- **문제**: 로그인 후 원래 보던 페이지로 보내 주려고 `?redirectUrl=`을 쓰는데, 여기에 바깥 주소를 넣으면 피싱에 악용될 수 있습니다.
- **처음 시도**: `/`로 시작하고 `//`로 시작하지 않으면 허용 → `/\t/evil.com`처럼 탭 문자를 끼우면 브라우저가 무시해서 `//evil.com`이 되어 뚫렸습니다.
- **해결**: `new URL(url, 'http://localhost')`로 브라우저처럼 해석한 뒤 출발지(origin)가 그대로일 때만 경로를 돌려줍니다. 우회 사례 8개로 확인했습니다.
- 같은 이유로 접근 제어도 **허용 목록**으로 바꿨습니다. 실수해도 "열려야 할 페이지가 잠기는" 쪽으로만 틀리게 됩니다. 그래서 나중에 만든 `/trash`는 아무것도 안 해도 로그인한 사람만 들어옵니다.

### 3. 등록 시각이 비어 있음 (DB 기본값 누락)

- **증상**: 등록순 정렬을 만들다가, 할 일의 `created_at`이 비어 있을 수 있다는 걸 발견했습니다.
- **원인**: 스키마에서 `profiles.created_at`에는 `default now()`가 있었는데 `todos.created_at`에는 빠져 있었고, 코드도 등록할 때 값을 넣지 않았습니다.
- **해결**: SQL로 빈 값을 채우고 `default now()` · `not null`을 추가했습니다. 저장소의 `schema.sql`도 같이 고쳐 기록을 맞췄습니다.
- **배운 점**: 화면에서 안 보이는 값도 DB 제약(`not null`)으로 막아 두면, 문제가 생겼을 때 조용히 넘어가지 않고 바로 드러납니다.
