## 1. 로그아웃 후 회원가입 링크가 로그인 화면으로 튕김

- **증상**: 로그아웃 → `회원가입` 클릭 → `/sign_in?redirectUrl=%2F`로 다시 이동.
- **원인**: Next는 링크가 화면에 보이면 그 페이지를 미리 받아 둡니다(prefetch). 로그인 상태일 때 받아 둔 `/sign_up`은 "로그인했으니 홈으로" 응답이었습니다. 로그아웃 뒤에도 브라우저가 이 저장본(라우터 캐시)을 그대로 썼습니다.
- **해결**: 로그아웃이 성공하면 `router.push` 대신 `window.location.replace('/sign_in')`로 페이지를 새로 엽니다. 저장본이 모두 비워집니다.

## 2. `.next/dev/types/validator.ts` 빌드 에러

- **증상**: 이미 지운 `app/page.js`를 찾지 못한다는 타입 에러로 빌드가 실패.
- **원인**: Next가 만들어 둔 타입 파일(`.next` 폴더)이 지우기 전 파일 목록을 기억하고 있었습니다.
- **해결**: `rm -rf .next` 후 다시 빌드. `.next`는 빌드 결과물이라 지워도 다시 만들어집니다.

## 3. 오픈 리다이렉트 막기 (`getSafeRedirect`)

- **문제**: 로그인 후 `?redirectUrl=` 주소로 보내 주는데, 여기에 바깥 사이트를 넣으면 피싱에 쓰일 수 있습니다.
- **처음 시도**: `/`로 시작하고 `//`로 시작하지 않으면 허용 → `/\t/evil.com`처럼 탭 문자를 끼우면 브라우저가 무시해서 `//evil.com`이 되어 뚫립니다.
- **해결**: `new URL(url, 'http://localhost')`로 브라우저처럼 주소를 해석한 뒤, 출발지(origin)가 그대로일 때만 경로를 돌려줍니다. 나머지는 모두 `/`로 보냅니다. 우회 사례 8개로 확인했습니다.

## 4 · 5. 접근 제어: 허용 목록 방식

- **문제**: 차단 목록 방식은 "막을 페이지"를 하나씩 적는 방식입니다. `/trash`처럼 새 페이지를 만들고 추가하는 걸 잊으면 로그인 없이 열리고, 에러도 나지 않아 알아채기 어렵습니다.
- **해결**: "열어 둘 페이지"(`/sign_in`, `/sign_up`)만 적고 나머지는 전부 막았습니다. 새 페이지는 기본으로 잠겨 있습니다.
- **추가 문제**: `startsWith('/sign_in')`은 `/sign_in_admin`까지 허용합니다. 주소가 똑같거나 그 아래 경로(`/sign_in/...`)일 때만 허용하도록 `isAuthPath()`를 만들었습니다.

## 6. 탈퇴한 계정이 로그인됨

- **원인**: Supabase는 DB 칸 이름을 그대로 돌려줍니다(`deleted_at`). 코드는 `deletedAt`을 읽어서 항상 `undefined`였습니다.
- **해결**: `profile.deleted_at`으로 읽기. 같은 실수를 막으려고 할 일 데이터는 DB 모양 → 앱 모양 변환을 `todoConverter.ts` 한 곳에 모았습니다.

## 7. 비밀번호 trim

- **원인**: 회원가입에서만 비밀번호를 trim 해서, `' abc12345'`로 가입하면 `'abc12345'`가 저장되고 로그인은 `' abc12345'`로 시도해서 실패했습니다.
- **해결**: 비밀번호는 가입 · 로그인 모두 trim 하지 않습니다(공백도 비밀번호의 일부, NIST 가이드라인). 이메일만 trim 합니다.

## 8. 조회 실패가 "할 일 없음"으로 보임

- **원인**: 조회에 실패하면 빈 배열 `[]`을 돌려줘서, DB 문제와 진짜 빈 목록을 구분할 수 없었습니다.
- **해결**: 에러를 던져서 에러 화면(`error.tsx`)이 "다시 시도"를 보여 주게 했습니다.

## 9. 목록이 갱신되지 않음

- **원인**: `useState(initialItems)`는 처음 값만 기억합니다. 서버가 새 목록을 보내도 state는 처음 값 그대로였습니다.
- **해결**: 서버에서 받은 props를 그대로 쓰고, 서버 응답 전까지만 `useOptimistic`으로 바뀐 모습을 미리 보여 줍니다. 실패하면 원래 값으로 자동으로 돌아갑니다.

## 10. 잘못된 상세 주소에서 에러 화면

- **원인**: `/todo/abc`의 `abc`를 그대로 DB에 보내면 id 형식(uuid) 에러가 나서 404 대신 에러 화면이 떴습니다.
- **해결**: DB에 묻기 전에 `isUuid()`로 검사하고, 형식이 틀리면 바로 "없음(404)"으로 처리합니다.

## 11 · 12. Next.js 16에서 바뀐 것

- **`proxy.ts`**: 예전 `middleware.ts`가 `proxy.ts`로 바뀌었습니다. 모든 요청이 페이지에 닿기 전에 로그인 쿠키를 갱신하고 접근을 막습니다.
- **Cache Components**: 쿠키, 주소 값(`params`, `searchParams`)처럼 요청마다 달라지는 값은 `<Suspense>` 안에서 읽어야 합니다. 바깥에서 읽으면 빌드 에러가 납니다. 그래서 헤더 사용자 메뉴, 로그인 폼, 목록 · 상세 페이지를 `<Suspense>`로 감쌌습니다.
- **`params`가 Promise**: 상세 페이지는 `params.then(({ id }) => <Content id={id} />)`처럼 Suspense 안에서 꺼냅니다.

## 13. 작업하면서 생긴 실수

- 코드를 붙여 넣고 저장하지 않아 빈 파일로 남은 적이 여러 번 있었습니다 → 빌드 전에 파일이 저장됐는지 먼저 확인합니다. (VS Code 자동 저장 Auto Save를 켜 두면 편합니다)
- 자동완성이 엉뚱한 import(`ToastActionState`, `ReactDOMServerReadableStream` 등)나 오타(`ActionSate`, `stirng`)를 넣었습니다 → 빌드 전에 import 줄을 먼저 확인합니다.
